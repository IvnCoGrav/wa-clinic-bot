# Audit 001: Anti-Slop UI/UX Admin Dashboard

- **Tanggal:** 2026-11-10
- **Mode antislop:** AFTER (audit read-only, tidak ada file sumber yang diubah)
- **Ruang lingkup:** `packages/admin-dashboard` (204 file UI, 60 rute, 2 gerbang desain) + `index.html`, `manifest.json`, `design.md`
- **Metode bukti:** pembacaan kode, penghitungan otomatis (scanner lokal), matematika kontras token, Lighthouse, dan pemuatan aplikasi nyata di `http://localhost:5199/admin/`

- **Status eksekusi:** 0 perbaikan dijalankan. Tidak ada kode sumber, test, atau CSS yang diubah. Menunggu persetujuan nomor temuan.

## Arah Desain (R-37)

`design.md` ada di root repo, tetapi **basi dan bertentangan dengan kode**:

1. Dokumen menyuruh memakai hex mentah (`bg-white`, `#008069`, `border-[#e9edef]`), sedangkan gerbang `check:tokens` justru melarang hex mentah. Dokumen mengajari hal yang diblokir oleh gerbang repo sendiri.
2. Dokumen mencentang "High-contrast typography (WCAG AA compliant)" dan "Clear hover, active, focus, and loading states for every clickable element" sebagai sudah selesai, padahal ada kegagalan kontras terukur (C-5 Evidence Over Claims).
3. Tidak ada dials ENERGY / RHYTHM / MOTION, tidak ada alasan pemilihan tipografi, tidak ada mood. Akibatnya tidak ada ukuran "hidup" yang bisa diuji.

Identitas yang ada sebenarnya sah dan khas: palet hijau WhatsApp (`#008069`), kanvas `#f0f2f5`, sudut `rounded-xl`/`rounded-2xl`, angka tabular. Ini bukan slop. Masalahnya bukan arah, melainkan **arah yang tidak dijaga**.

## Temuan (urut prioritas)

Prioritas mengikuti tier aturan: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

### HIGH (Hard Gate, tidak ada pengecualian)

**1. Teks putih di atas permukaan solid tidak terbaca di mode gelap.** `R-25`
- Bukti: token mode gelap sengaja dibuat terang (`accent #00a884`, `danger #f87171`, `warning #f59e0b`, `info #38bdf8`), sehingga teks putih di atasnya terukur 3,03 / 2,77 / 2,15 / 2,14 : 1. Lighthouse halaman login melaporkan kegagalan `color-contrast` 3,02:1 pada tombol "Masuk Sekarang". Ada 110 lokasi `text-white` di atas permukaan solid yang tidak memakai token `text-on-solid` / `text-accent-ink`, padahal kedua token itu sudah disediakan khusus untuk kasus ini.
- Alasan satu baris: token sudah benar, pemakaian yang salah, jadi separuh tombol dan chip menjadi tidak terbaca saat gelap.
- Arah perbaikan: ganti `text-white` menjadi `text-on-solid` (permukaan semantik) atau `text-accent-ink` (permukaan accent) di seluruh 110 lokasi, lalu tambahkan aturan larangan `text-white` berdampingan dengan `bg-*` solid ke `check:tokens` supaya tidak kembali.

**2. Label form tidak terhubung ke input.** `R-39`
- Bukti: di halaman login, kedua `<label>` punya `htmlFor=""` dan kedua `<input>` tidak punya `id` (dibaca langsung dari DOM: `labelHtmlFor: ["", ""]`, `firstInputId: ""`). Pembaca layar tidak mengumumkan nama field, dan klik label tidak memfokuskan input.
- Alasan satu baris: field paling kritis di seluruh aplikasi tidak punya nama aksesibel.
- Arah perbaikan: halaman login memakai komponen `Input` bersama (sudah punya `htmlFor` otomatis), atau pasang `id` + `htmlFor` eksplisit. Tambahkan satu test render yang memastikan setiap `input` punya nama aksesibel.

**3. 45 modal buatan sendiri tanpa semantik dialog dan tanpa tombol Escape.** `R-32`, `R-39`
- Bukti: hanya 1 file memakai komponen `Modal` bersama; 45 file membuat overlay sendiri (`fixed inset-0` + `bg-black/`); hanya 5 file memakai `role="dialog"`; hanya 15 file menangani `Escape`. Termasuk dialog konfirmasi global di `UiFeedback.tsx`: tidak ada `role="dialog"`, `aria-modal`, `aria-labelledby`, focus trap, fokus awal, maupun penutupan dengan Escape.
- Alasan satu baris: pengguna keyboard bisa terlempar ke belakang dialog dan tidak bisa menutupnya tanpa mouse.
- Arah perbaikan: jadikan `Modal` bersama satu-satunya jalan membuat dialog (focus trap + Escape + `aria-modal` + kembalikan fokus), lalu migrasikan 45 overlay itu bertahap per modul. Dialog konfirmasi dan toast di `UiFeedback` diperbaiki lebih dulu karena dipakai semua halaman.

**4. 70 tombol ikon tanpa nama aksesibel.** `R-39`
- Bukti: dari 135 tombol yang isinya hanya ikon, 70 tidak punya `aria-label` / `aria-labelledby` / `title`. Sampel terverifikasi: `LocationPickerModal.tsx:170`, `LiveChatSyncModal.tsx:31`, `InvoiceGeneratorModal.tsx:531`, `DailyScheduleModal.tsx:115` (semuanya tombol tutup dengan `<X />` saja).
- Alasan satu baris: tombol tutup terbaca "tombol" tanpa keterangan, di semua dialog.
- Arah perbaikan: beri `aria-label="Tutup"` (atau konteksnya) pada setiap tombol ikon, dan tambahkan pemeriksaan otomatis di build untuk tombol yang isinya hanya ikon.

**5. Halaman sisa alat desain dapat diakses publik tanpa login.** `R-38`, `C-3`, `R-24`
- Bukti: `StitchShowcase.tsx` terpasang di 4 rute publik (`/stitch-preview`, `/stitch`, `/admin/stitch-preview`, `/admin/stitch`) tanpa `ProtectedRoute`. Isinya "WhatsApp Clinic Bot - Google Stitch Showcase Canvas" dengan badge "Ready for Stitch Import", 241 warna hex, emoji bintang, dan label "PRIORITAS 1 • HARIAN & REAL-TIME". Isinya bukan fitur produk.
- Alasan satu baris: artefak proses desain bocor ke produksi dan bisa dibuka siapa saja.
- Arah perbaikan: hapus rute publiknya, atau pindahkan ke environment pengembangan saja. Catat keputusan ini di `docs/KNOWN_ISSUES.md` karena sebelumnya file ini sengaja dikecualikan dari gerbang paritas (keputusan D-5).

**6. Panduan desain tidak sinkron dan kedua gerbang desain merah.** `R-37`, `R-31`
- Bukti: `npm run check:tokens` GAGAL (293 hex hardcode dari baseline 287; `src/utils/chatScheduleExtractor.ts`, `invoiceReadiness.ts`, `livechatNavigation.ts`, `livechatThread.ts`, `quickReplyReservation.ts`, dan `index.html` melewati batas 0). `npm run check:dark-parity` GAGAL (`AdminCopilotPanel.tsx`, 2 kelas palet tanpa `dark:`). `.github/workflows/ci.yml` membangun dashboard tetapi **tidak pernah menjalankan** `check:design`.
- Alasan satu baris: ada gerbang mutu, tetapi tidak dijalankan, jadi tidak ada yang menahan kemunduran.
- Arah perbaikan: perbaiki dua kegagalan itu, lalu tambahkan `npm run check:design` ke `ci.yml`. Perbarui `design.md` agar memakai nama token (bukan hex), mencantumkan dials ENERGY/RHYTHM/MOTION, dan menghapus klaim yang tidak terverifikasi.

**7. Karakter em dash dipakai di teks yang dilihat pengguna.** `R-02`
- Bukti: 123 baris non-komentar memuat em dash atau en dash, contoh nyata di UI: `LiveChatMessagePane.tsx:1327` "Catatan Internal — {nama}", `:1721` "Chat sandbox — balasan admin diblokir otomatis", `ReservationStatusIcon.tsx:82/100` "HOLD — slot ditahan sementara" dan "Pending — menunggu konfirmasi", `MetaPerformancePanel.tsx:189`, `TherapistUtilizationCard.tsx:7-8`, `LiveChatComposer.tsx:838`.
- Alasan satu baris: aturan Hard Gate, murah diperbaiki, dan tanda ini paling cepat dikenali sebagai tulisan mesin.
- Arah perbaikan: ganti dengan titik dua, koma, atau kurung. Komentar kode tidak termasuk cakupan.

**8. Emoji sebagai hiasan di teks UI.** `R-04`

Terpadat di `CreateReservationModal.tsx`: "⚠️ Konfirmasi Jadwal Bentrok", "✏️ Edit Data Reservasi", "👶 Anak #", "👩 Bunda / Umum", "🕒 Durasi Layanan", "☕ Buffer Jeda", "🏁 Selesai", "⚡ Saya", "🎯 {usia}". - Arah perbaikan: hapus dari teks UI; bila benar-benar perlu penanda, pakai ikon relevan atau teks saja. Prioritas: form reservasi dan toast.

**9. Animasi berulang tanpa henti.** `R-19`
- Bukti: 62 pemakaian `animate-pulse` / `animate-bounce` / `animate-ping`, termasuk titik status koneksi SSE (`LiveChatMonitor.tsx:770`), tombol "Selesai" yang berdenyut terus (`StaffToday.tsx:3514` lewat `animate-action-pulse`), dan indikator "menunggu" di `Reservations.tsx:2128` serta `TodayTreatments.tsx:2112/2219`.
- Alasan satu baris: gerak tanpa akhir menarik mata terus-menerus dan tidak pernah mengembalikan perhatian ke isi.
- Arah perbaikan: sisakan satu denyut hanya untuk status yang benar-benar live dan berhenti setelah beberapa detik; ganti sisanya jadi perubahan warna atau label.

**10. Blur dan bayangan dipakai sebagai default, bukan penanda elevasi.** `R-10`, `R-12`
- Bukti: 84 `backdrop-blur`, 45 di antaranya pada overlay modal yang sekaligus memakai `shadow-2xl` atau `shadow-xl` (100 pemakaian `shadow-lg` ke atas).
- Alasan satu baris: saat semua permukaan mengapung dan diburamkan, tidak ada lagi yang terasa di depan.
- Arah perbaikan: tetapkan tiga tingkat elevasi (datar, kartu, dialog) dan patuhi; blur hanya untuk satu atau dua elemen.

**11. Tipografi tidak benar-benar diputuskan.** `R-06`, `R-31`
- Bukti: `src/index.css:243` menyatakan `font-family: 'Plus Jakarta Sans'`, tetapi tidak ada `@font-face` maupun tautan font di `index.html`; `document.fonts` kosong (0 font dimuat) dan `body` akhirnya memakai stack Tailwind (`-apple-system, ..., Inter, ...`) yang juga tidak dimuat. Selain itu ada 833 pemakaian `text-[9px]`/`text-[10px]` dan default `text-xs` = 12px untuk tombol, input, dan tabel.
- Alasan satu baris: keputusan tipografi tertulis tapi tidak pernah terjadi, dan teks sekecil 9px sulit dibaca di HP terapis.
- Arah perbaikan: pilih satu keluarga font dan muat benar-benar (atau hapus deklarasinya dan akui stack sistem), lalu naikkan batas minimum teks ke 12px dengan varian 11px hanya untuk metadata yang tidak penting.

**12. Hierarki terbalik pada layar utama.** `C-3`, `R-20`, `R-14`
- Bukti: `Overview.tsx` menampilkan tepat 4 `KpiCard` berukuran identik (Total Percakapan, Reservasi Hari Ini, Omset Bulan Ini, AOV) tanpa satu pun yang menonjol. Judul halaman memakai `text-xl` (20px), sedangkan judul halaman `LiveChatMonitor.tsx:759` hanya `text-sm` sampai `text-base` (14-16px), sementara angka KPI memakai `text-2xl` sampai `text-3xl` (24-30px).
- Alasan satu baris: mata mendarat di angka, bukan di pertanyaan yang harus dijawab layar itu.
- Arah perbaikan: tentukan satu keputusan utama per layar (contoh: "jadwal mana yang berisiko hari ini"), besarkan pemimpinnya, dan turunkan sisanya jadi catatan.

**13. Tidak ada primitif state bersama, jadi empty / loading / error tidak seragam.** `R-27`
- Bukti: tidak ada komponen bernama `EmptyState`, `Skeleton`, atau `LoadingState` di `src/components` (204 file). Setiap halaman menulis state sendiri; ada halaman yang punya pesan bagus (`Overview.tsx:88`: "Gagal memuat metrik. Angka tidak ditampilkan agar tidak menyesatkan.") dan ada yang hanya spinner (fallback `App.tsx`).
- Alasan satu baris: state yang ditulis ulang 20 kali akan berbeda 20 kali, dan yang paling sering hilang adalah "mengapa kosong dan apa langkah berikutnya".
- Arah perbaikan: buat tiga komponen bersama (`EmptyState` dengan sebab + aksi, `SkeletonList`, `ErrorState` dengan tombol coba lagi), lalu pakai di halaman utama lebih dulu.

**14. Target sentuh di bawah 44px.** `R-03`
- Bukti: `index.css:426-428` menaikkan tinggi tombol di mobile hanya sampai `38px`; `Button` komponen `sm` = 32px dan `md` = 38px. `h-[22px]` dipakai untuk chip dan tag interaktif.
- Alasan satu baris: di HP terapis, 38px berarti sering salah tekan, terutama saat memegang bayi atau berdiri.
- Arah perbaikan: naikkan batas minimum aksi utama ke 44px di mobile (bukan 38px), sisakan 32-38px hanya untuk kontrol sekunder di dalam tabel.

**15. Sisa gaya yang tidak dipakai dan gradien teks.** `R-01`, `R-31`
- Bukti: `.gradient-text` (`index.css:461`) mendefinisikan gradien tiga warna untuk teks, tetapi kelas tersebut tidak dipakai di komponen mana pun (grep 0 pemakaian di `.tsx`). 9 `bg-gradient-*` lain dipakai pada banner status (amber, emerald, sky) yang punya fungsi, jadi lolos uji tujuan.
- Alasan satu baris: kode mati menyimpan pola yang nanti dipakai ulang tanpa alasan.
- Arah perbaikan: hapus `.gradient-text`, `.glass-panel`, dan `.glass-card` yang penamaannya menyesatkan (isinya justru solid putih).

## Yang Sudah Baik (jangan diutak-atik)

1. **Sistem token kontras lulus.** 45 kombinasi teks/latar diuji matematis: seluruh kombinasi teks di permukaan netral dan chip semantik lulus 4,5:1 pada mode terang maupun gelap. Satu-satunya kegagalan berasal dari kode yang tidak memakai token (temuan 1), bukan dari tokennya.
2. **Tidak ada angka palsu.** `Overview.tsx:88` menyembunyikan metrik saat gagal memuat dengan alasan eksplisit, sesuai R-17.
3. **Tidak ada `window.confirm` / `window.alert`.** Semua konfirmasi memakai `useUiFeedback` (49 file), sesuai aturan repo.
4. **`prefers-reduced-motion` dihormati** secara global (`index.css:743-752`) dan khusus pada denyut tombol.
5. **Safe area iOS ditangani serius** (`viewport-fit=cover`, token `--sat/--sab`, penyesuaian keyboard) dan zoom tidak diblokir (`user-scalable` tidak dipakai).
6. **Semua 42 `<img>` punya `alt`**; 37 di antaranya juga punya dimensi atau kelas ukuran.
7. **Tabel sudah dibungkus `overflow-x-auto`** lewat komponen `Table`, jadi tidak ada tabel yang memecahkan layar.
8. **Tidak ada patch script** yang menulis ulang CSS/sumber (R-33 bersih).
9. **Radius dipakai sebagai hierarki** (±48 kontrol berbentuk pil lawan 1.154 pemakaian `rounded-xl`), bukan serba pil.

## Rencana Perbaikan (BELUM dieksekusi, menunggu persetujuan)

Urutan mengikuti dependency dan blast radius. Setiap fase ditutup gerbang regresi.

**Fase 1, fondasi token (blast radius kecil, dampak terbesar)**
1. Ganti 110 `text-white` di atas permukaan solid menjadi `text-on-solid` / `text-accent-ink`.
2. Tambahkan aturan `check:tokens` yang menolak `text-white` berdampingan dengan `bg-accent|bg-success|bg-danger|bg-warning|bg-info|bg-violet`.
3. Selaraskan `check:dark-parity` untuk `AdminCopilotPanel.tsx`.
4. Terima bila: `npm run check:design` hijau; Lighthouse login >= 0,95 dan kategori `color-contrast` hilang di kedua tema.

**Fase 2, aksesibilitas form dan dialog (blast radius menengah)**
1. Login: `id` + `htmlFor` + `autoComplete` + `inputMode`; pakai komponen `Input` bersama.
2. `UiFeedback`: `role="dialog"`, `aria-modal`, `aria-labelledby`, Escape, fokus awal, kembalikan fokus; toast diberi `role="status"` + `aria-live="polite"` + tombol tutup berlabel.
3. Migrasikan 45 overlay buatan sendiri ke `Modal` bersama, 5 file per putaran.
4. 70 tombol ikon diberi `aria-label`; tambahkan test render yang gagal bila tombol ikon tanpa nama.
5. Terima bila: uji Tab/Shift+Tab/Escape lulus di login, dialog konfirmasi, dan 2 modal tersibuk; Lighthouse aksesibilitas >= 0,95.

**Fase 3, pembersihan konten (blast radius rendah)**
1. Hapus atau kunci 4 rute `StitchShowcase`.
2. Ganti 123 em dash di teks UI.
3. Hapus emoji dari teks UI, mulai dari `CreateReservationModal.tsx` dan toast `Layout.tsx`.
4. Terima bila: 0 em dash di luar komentar, 0 emoji di string JSX, rute `/stitch*` tidak dapat diakses publik.

**Fase 4, tipografi dan state (blast radius menengah)**
1. Putuskan satu keluarga font dan muat benar-benar, atau hapus deklarasinya.
2. Naikkan minimum teks jadi 12px, 11px hanya untuk metadata.
3. Buat `EmptyState`, `SkeletonList`, `ErrorState`; pasang di Overview, LiveChat, Reservations, TodayTreatments.
4. Naikkan target sentuh aksi utama mobile ke 44px.
5. Terima bila: tidak ada teks di bawah 11px; empat halaman utama punya tiga state dengan sebab dan aksi.

**Fase 5, arah desain dan penjagaan (blast radius rendah, efek jangka panjang)**
